---
title: API 密钥
description: 密钥前缀与作用域、密钥来源，以及密钥会开启和不会开启的功能
---

本地推理无需账号，也无需密钥。Xybrid API 密钥用于让应用或 CLI 向 Xybrid
平台认证：云端网关、路由建议和轨迹接收（ingest）。**密钥本身永远不会开启轨迹导出**；
导出需要另行显式配置。

## 密钥格式

| 前缀 | 环境 |
|------|------|
| `sk_live_` | Live：生产环境应用 |
| `sk_test_` | Test：开发与 CI |

两种密钥的认证方式相同；前缀记录的是创建密钥时选择的环境，而不是它的作用域（参见[作用域](#作用域)）。旧版 Xybrid
文档中出现的 `xy_live_...` 占位符并不是平台签发过的密钥格式。

不要把密钥提交到源代码仓库。请从环境变量或已加入 gitignore 的文件中读取，例如
Android 的 `local.properties`，或 iOS 中由构建配置引入的 `.xcconfig` 文件。

## 密钥来源

- **控制台。** 登录 [console.xybrid.dev](https://console.xybrid.dev)，打开项目的
  **API keys** 页面并创建密钥。你可以选择 live 或 test；密钥只在创建时显示一次。
  控制台创建的密钥拥有完整（full）作用域，并可随时在控制台中吊销。
- **代理注册（agent signup）。** 编程代理可以在无人登录的情况下为项目创建一个临时工作区。
  它的密钥是客户端（client）作用域的 `sk_live_` 密钥；如果没有人认领，工作区会过期。
  代理注册尚未全面开放，参见[临时工作区](#临时工作区)。

## 作用域

| 操作 | 客户端作用域 | 完整作用域 |
|------|:------------:|:----------:|
| 向 Xybrid ingest 发送轨迹，以及反馈或评估日志 | 是 | 是 |
| 云端网关：对话、语音合成、转写、翻译、嵌入、模型与音色目录 | 是 | 是 |
| 路由建议与 skill 解析 | 是 | 是 |
| 通过 API 读取轨迹、遥测数据或已存储的内容 | 否 | 是 |
| Xybrid MCP 服务器 | 否 | 是 |
| 创建或吊销密钥，管理成员与邀请 | 否 | 否 |

密钥与成员管理始终需要已登录的控制台会话。认领临时工作区不会改变其密钥的作用域：
客户端密钥仍是客户端密钥。如需使用 MCP 或通过 API 读取数据，请在控制台中创建完整作用域的密钥。

随应用一起发布的密钥（移动端、桌面端、Web 或游戏构建）可能被人从安装包中提取，
并在其作用域内被提取者使用。**控制台只能创建完整作用域的密钥**，因此发布构建中的控制台密钥
会让提取者通过 API 和 MCP 服务器读取该密钥所属项目的轨迹，包括这些轨迹采集到的提示词和输出。
内容采集默认开启（参见[内容策略](#内容策略)）。要限制发布出去的密钥所能暴露的内容：

- [只导出元数据](#内容策略)，这样就不会存储提示词或输出。
- 让每个发布的应用使用单独的项目和密钥。
- 或者不让导出用的密钥进入设备：把轨迹发送到你自己运行的 OpenTelemetry Collector，
  再由 Collector 携带密钥转发到 Xybrid ingest。
- 密钥泄露时吊销并更换。

## 认证与轨迹导出相互独立

把密钥交给 SDK 只会配置云端认证。只有在配置 Xybrid 可观测性预设（它单独接收一个密钥，
可以是同一个密钥），或将 SDK 指向你自己的 OpenTelemetry Collector 时，才会开始导出轨迹。

| SDK | 云端认证 | 将轨迹导出到 Xybrid |
|-----|----------|---------------------|
| Flutter | `Xybrid.init(apiKey: key)` | `Xybrid.init(observability: ObservabilityConfig.xybrid(apiKey: key))` |
| Swift | `Xybrid.initialize(apiKey: key)` | `try Xybrid.Observability.xybrid(apiKey: key).start()` |
| Kotlin | `Xybrid.init(context, apiKey = key)` | `Xybrid.Observability.xybrid(key).start()` |
| React Native | `Xybrid.initialize({ apiKey: key })` | `ObservabilityConfig.xybrid(key).init()` |
| Unity | `XybridClient.Initialize(apiKey: key)` | `XybridClient.InitializeObservability(ObservabilityConfig.Xybrid(key))` |
| Rust | `xybrid_sdk::init().api_key(key).run()` 或 `XYBRID_API_KEY` | `xybrid_sdk::init().observability(ObservabilityConfig::xybrid(key)).run()` |
| Python | `xybrid.init(api_key=key)` | `xybrid.XybridObservabilityConfig.xybrid(key).init()` |
| CLI | `--api-key` 或 `XYBRID_API_KEY` | 添加 `--observability` |

Xybrid 预设**只发送轨迹**，目标为 `https://ingest.xybrid.dev/v1/traces`。它不配置指标或日志，
因此使用该预设时反馈与评估辅助函数会返回 `false`。在 CLI 中，`OTEL_SDK_DISABLED=true` 会禁用导出。

## 导出哪些内容

### 内容策略

开启导出后，默认会在 span 上采集提示词、系统提示词、输出和推理内容，每个属性上限为 16 KiB。
如需只导出元数据：

| SDK | 仅元数据 |
|-----|----------|
| Flutter | `ObservabilityConfig.xybrid(apiKey: key, metadataOnly: true)` |
| Swift、Kotlin | `.metadataOnly()` |
| React Native | `.setMetadataOnly(true)` |
| Unity | `.WithMetadataOnly()` |
| Rust | `.content(ContentPolicy::metadata_only())` |
| Python | `config.set_metadata_only(True)` |
| CLI | `OTEL_INSTRUMENTATION_GENAI_CAPTURE_CONTENT=no_content` |

仅元数据模式会省略受管控的内容：消息、输出、推理、工具调用载荷和提示词变量。
它仍会导出模型、耗时和 token 用量、服务与设备描述、工具定义（schema），以及你的代码附加的一切：
自定义属性、会话 ID 等标识符，以及显式提供的错误信息。它不是通用的脱敏器，
请不要把密钥或个人数据放进标识符和属性中。

### 资源采样

资源采样会在每次运行前后记录 CPU、内存、温控和电量读数，作为 `xybrid.genai.resource.*`
span 属性。它在所有 SDK 和 CLI 中**默认关闭**。可通过 Rust（`.resource_telemetry(...)`）、
Flutter（`resourceTelemetry`）或 `XYBRID_RESOURCE_TELEMETRY` 环境变量开启。

另外，检测到的操作系统、架构、芯片和内存容量默认会附加到轨迹资源上
（`XYBRID_TELEMETRY_OPTOUT=1` 可省略）。主机名永远不会发送，也不会生成设备标识符：
只有你自行提供时才会设置 `device.id`。

## 临时工作区

通过代理注册创建的工作区在被人认领之前都是**临时（provisional）**的。代理注册尚未全面开放；
本节说明这类工作区的生命周期。

| 创建后 | 未认领的工作区 |
|--------|----------------|
| 第 0 天 | 创建时附带一个客户端作用域的 `sk_live_` 密钥，立即可用。代理会给你一个私密的认领链接。 |
| 第 7 天 | 密钥停止工作：轨迹接收和云端网关都会拒绝它。本地推理不受影响。 |
| 第 7 至 14 天 | 仍可认领该工作区，认领后密钥恢复可用（除非你选择轮换密钥）。 |
| 第 14 天 | 工作区及其密钥被删除。它发送的轨迹会保留到过期为止（目前最长 90 天），其云端网关调用记录目前尚未设定过期时间。 |

认领方法：打开认领链接，使用 GitHub 登录控制台，确认工作区信息后认领。该链接是私密的：
任何打开它并登录的人都能认领这个工作区。认领后的工作区会保留其项目和轨迹历史，
上述期限也不再适用。在认领之前，它可以发送轨迹、使用模型仓库，并每天发起少量云端网关请求。

认领后的工作区也会保留其密钥，除非你在认领表单中勾选 **Rotate the keys**（轮换密钥）。
轮换会吊销该工作区的密钥（即代理写入项目文件的那些密钥），并为每个项目生成一个新的客户端作用域密钥，
只显示一次。在你用新密钥替换旧密钥之前（例如 `.env`、`local.properties` 或 `.xcconfig`
文件中的 `XYBRID_API_KEY`），应用的导出和云端请求都会被拒绝。被吊销的密钥收到的是普通的 401，
因此不会表现为[工作区通知](#工作区通知)。

### 工作区通知

每次通过 Xybrid 预设导出时，轨迹接收服务都会在 `X-Xybrid-Workspace` 响应头中报告工作区状态：

- 临时密钥的导出被接受时，响应头为 `provisional; expires_at=<RFC 3339 时间>`，即密钥的截止时间。
- 截止时间之后，ingest 返回 HTTP 401，响应头为 `expired`，并附带一个 code 为 16、message 为
  `workspace_expired` 的 `google.rpc.Status`，编码与请求一致（protobuf 或 OTLP/JSON）。

包含 Xybrid 工作区反馈（workspace feedback，参见[更新日志](https://github.com/xybrid-ai/xybrid/blob/master/CHANGELOG.md)）的
SDK 与 CLI 版本会处理这些响应：

- **基于 Xybrid 运行时的 SDK**（Flutter、Swift、Kotlin、React Native、Unity、Rust 和 Python）。
  当 ingest 报告工作区已过期时，SDK 会在本次会话的剩余时间内停止向 Xybrid 发送轨迹，不再重试。
  不再发送的 span 会在导出器统计中计为 dropped，绝不会计为已导出。
  本地推理、本地 span 以及其他所有导出目标都会继续运行。

  SDK 还会在每个会话中为临时密钥记录一条带有截止时间的 info 日志，并在停止导出时记录一条警告。
  这些消息出现在哪里取决于平台：

  | 平台 | 通知出现的位置 |
  |------|----------------|
  | Android（任意绑定） | logcat，标签 `xybrid` |
  | iOS（任意绑定） | 统一日志，子系统 `dev.xybrid.sdk` |
  | Rust | 你的应用安装的 `log` 后端，target 为 `xybrid_sdk` |
  | 桌面端：Python、macOS 应用、Flutter 与 Unity 桌面构建、Unity 编辑器 | 不会出现：没有安装日志器。导出仍会停止；请关注导出器统计中的 dropped 计数。 |

- **CLI。** 命令完成最后一次导出后，CLI 会把通知打印到 stderr：每次因工作区过期而被拒绝轨迹的
  运行都会打印；密钥处于临时状态时，最多每天打印一次并附上截止时间。`-q`、JSON 输出、
  CI 环境以及 `XYBRID_QUIET=1` 都会关闭这些通知。
- **不包括：** JavaScript 包 `@xybrid/observability`（浏览器预览版使用它）。它的
  `xybridTracesPreset` 不读取这些响应：截止时间之后它仍会继续发送，而 ingest 会以 401 拒绝每次导出。

只有上述明确的过期响应才会停止导出。普通的 401、限流或服务器错误都不会，
OpenTelemetry Collector 或其他端点也永远不受影响。

**认领后恢复导出。** 认领后密钥会立即恢复，但已经停止导出的会话会保持停止状态。
重启应用，或再次初始化可观测性，即可恢复导出；CLI 会在下一条命令时恢复。
如果认领时轮换了密钥，请先替换项目中的密钥。导出停止期间记录的轨迹不会被重新发送。
