---
title: xybrid trace
description: 分析显式导出的 OTLP 轨迹文件
---

`xybrid trace FILE` 分析由 `xybrid run --trace-export FILE` 创建的 OTLP/JSON
文件。轨迹属于当前运行，不会自动保存到会话目录。

## 用法

```bash
xybrid run --model kokoro-82m --input-text "Hello" --trace-export trace.json
xybrid trace trace.json
xybrid trace trace.json --export summary.json
```

| 参数 | 说明 |
|------|------|
| `FILE` | 必填，OTLP/JSON 轨迹文件的路径 |
| `--export PATH` | 同时把分析摘要写入指定文件 |

命令输出 JSON 摘要，包含操作计数、逻辑请求的 token 用量，以及 `operations`
数组。每个操作包含轨迹与跨度 ID、父跨度、耗时、模型、执行位置、路由、加载触发原因、
错误分类，以及已测得的用量和时间。不可用的测量值保持为 `null`。
重试跨度保留自身用量，但不会被重复计入逻辑请求总量。

## 本地采集与远程导出

`xybrid run --trace` 显示当前运行的本地轨迹；`--trace-export PATH` 把轨迹写为
OTLP/JSON 文件。这两个选项都不会启用远程导出。远程导出需另行配置
`--observability` 或 Collector 环境变量。`OTEL_SDK_DISABLED=true` 禁用远程导出，
本地采集仍然可用。

轨迹文件可能包含应用数据。分析摘要只保留操作元数据和测量值，不复制提示词或输出内容。

## 迁移

把 `xybrid trace --latest` 或 `--session ID` 替换为显式文件路径。
旧版会话日志和 Chrome trace 文件不受支持；新采集请使用
`xybrid run ... --trace-export FILE`。
