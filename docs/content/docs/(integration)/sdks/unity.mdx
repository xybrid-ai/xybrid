The Unity SDK (`ai.xybrid.sdk`) provides C# bindings to the Xybrid runtime via BoltFFI, enabling on-device ML inference in Unity games and applications.

## Installation

The package contains only the C# API. It downloads the native libraries for its version from the matching [GitHub Release](https://github.com/xybrid-ai/xybrid/releases), verifies their SHA-256, and installs them into `Assets/Xybrid/Plugins/`: the editor's own platform on first import, and the build target's before a player build if they aren't installed yet. The first import needs network access. To download them again, use **Xybrid > Native Libraries > Download for Current Editor** or **Download for Active Build Target**.

Minimum Unity version: **2021.3 LTS**

### OpenUPM (recommended)

Xybrid is published on [OpenUPM](https://openupm.com/packages/ai.xybrid.sdk/). With the [OpenUPM CLI](https://openupm.com/docs/getting-started-cli.html):

```bash
openupm add ai.xybrid.sdk
```

Without the CLI, open **Edit > Project Settings > Package Manager** and add a scoped registry:

| Field | Value |
|-------|-------|
| Name | `OpenUPM` |
| URL | `https://package.openupm.com` |
| Scope(s) | `ai.xybrid` |

Then install **Xybrid SDK** from **Window > Package Manager > My Registries**. To declare the registry in `Packages/manifest.json` instead, or to install from a local clone, see the [package README](https://github.com/xybrid-ai/xybrid/tree/master/bindings/unity#installation).

### Git URL

In Unity, open **Window > Package Manager > + > Add package from git URL** (**Install package from git URL** in Unity 6) and enter:

```
https://github.com/xybrid-ai/xybrid.git?path=/bindings/unity
```

Without a tag, Unity installs the newest commit on `master`, but the native libraries come from the release named by that commit's `package.json` version, normally the latest release. To pin a release, append its tag after the path, as in `?path=/bindings/unity#v<version>`. Tags are listed on [GitHub Releases](https://github.com/xybrid-ai/xybrid/releases).

## Initialization

Initialize the SDK once at startup:

```csharp
using Xybrid;

void Awake()
{
    XybridClient.Initialize();
}
```

`Initialize()` is thread-safe and idempotent — multiple calls are no-ops.

On Android, models are cached under `Application.persistentDataPath/xybrid` (the SDK is given its `models` subfolder and keeps runtime-ready files beside it in `extracted`). To use another folder, call `XybridBolt.XybridBolt.InitSdkCacheDir(path)` before loading or listing any model; the first folder set wins.

Inference runs entirely on-device whether or not you authenticate. Pass an `apiKey` to light up the [dashboard](https://dashboard.xybrid.dev) — that single call starts the telemetry exporter, and your `model.Run(...)` calls automatically emit execution traces:

```csharp
XybridClient.Initialize(apiKey: "xy_live_...");
```

Without a key, telemetry is disabled and the first inference logs a one-shot hint pointing at the dashboard (suppress with the `XYBRID_QUIET=1` environment variable). Get a free key at [dashboard.xybrid.dev](https://dashboard.xybrid.dev). For a self-hosted dashboard, also pass `ingestUrl`. For advanced telemetry settings (batch size, flush interval, device attributes), build a `TelemetryConfig` and call `XybridClient.InitializeTelemetry` instead.

## Quick Start

```csharp
using Xybrid;

// Load and run in one line
var model = XybridClient.LoadModel("kokoro-82m");
using (var envelope = Envelope.Text("Halt! None shall pass without the king's seal."))
using (var result = model.Run(envelope))
{
    result.ThrowIfFailed();
    Debug.Log($"Output: {result.Text}");
    Debug.Log($"Latency: {result.LatencyMs}ms");
}
```

## Download Progress

`load()` blocks until the weights are on disk, so it has no progress to report
while it runs. Start the download separately and watch it:

```csharp
using var download = ModelLoader.FromRegistry("qwen3-0.6b").StartDownload();
while (!download.IsFinished())
{
    // Status() never blocks, so it is safe once per frame.
    slider.value = download.Status().Progress;
    yield return null;
}

using var loader = ModelLoader.FromRegistry("qwen3-0.6b");
var model = loader.Load();   // cached: returns at once
```

`progress` spans every file the model needs — weights plus companions such as a
vision projector — and never moves backwards, so the bar neither restarts per
file nor rewinds when a download retries. `totalBytes` is null when the source
publishes no size (a Hugging Face repo); `downloadedBytes` is exact either way,
which is what you need for megabytes, speed and time remaining.

Cancelling the consuming task only unsubscribes from updates. Call `cancel()`
to stop the transfer itself — it takes effect within one chunk read and
discards the partial file.

## Live Transcription

`run()` transcribes a finished audio buffer. A session transcribes speech *as
it arrives*, which is what dictation and live captioning need.

Audio must be PCM **float32, mono, 16 kHz** — converting from the platform's
microphone format is the caller's job.

```csharp
using var session = model.Stream(StreamingConfigs.VoiceActivity(vadModelDir, language: "en"));

// Drive the UI from the partial stream.
await foreach (var partial in session.Partials(cancellationToken))
{
    label.text = partial.Text;
}

// From the Microphone clip, converted to float mono 16 kHz:
session.Feed(pcm);

string transcript = session.Flush();
```

Partial text is **cumulative, not a delta**: render each one in place of the
previous rather than appending. A partial produced before you subscribe is
delivered immediately, so the opening words of an utterance are never lost.

`flush()` ends the session and returns the full transcript — and reports an
error if any chunk failed to transcribe, because that audio is gone and the
transcript would otherwise look complete. `cancel()` ends the session and
discards queued audio.

Voice-activity detection cuts chunks on speech boundaries instead of a fixed
clock, which avoids the stutter you get when a window lands mid-word. It needs
a Silero VAD model directory containing a `model.onnx`; none ships with the
SDK, and without one the engine falls back to fixed windows.

## Result Handling

```csharp
using (var result = model.Run(envelope))
{
    if (result.Success)
    {
        Debug.Log($"Output: {result.Text}");
        Debug.Log($"Latency: {result.LatencyMs}ms");
    }
    else
    {
        Debug.LogError($"Error: {result.Error}");
    }
}

// Or throw on failure
using (var result = model.Run(envelope))
{
    result.ThrowIfFailed();
    // Safe to use result.Text here
}
```

### InferenceResult Properties

| Property | Type | Description |
|----------|------|-------------|
| `Success` | `bool` | Whether inference succeeded |
| `Error` | `string` | Error message if failed |
| `Text` | `string` | Text output (ASR, LLM) |
| `LatencyMs` | `uint` | Inference latency in ms |

## Conversation Context

Multi-turn LLM conversations with automatic history management:

```csharp
using (var context = new ConversationContext())
{
    context.SetSystem("You are a wise elder in a forest village. You speak in short, cryptic phrases.");
    context.SetMaxHistoryLength(50); // FIFO pruning after 50 messages

    // First turn
    context.Push("Where is the lost temple?", MessageRole.User);
    using (var envelope = Envelope.Text("Where is the lost temple?"))
    using (var result = model.Run(envelope, context))
    {
        result.ThrowIfFailed();
        context.Push(result.Text, MessageRole.Assistant);
        Debug.Log(result.Text);
    }

    // Second turn (has full history)
    context.Push("What dangers await there?", MessageRole.User);
    using (var envelope = Envelope.Text("What dangers await there?"))
    using (var result = model.Run(envelope, context))
    {
        result.ThrowIfFailed();
        context.Push(result.Text, MessageRole.Assistant);
        Debug.Log(result.Text);
    }

    // Clear history but keep system prompt
    context.Clear();
}
```

### ConversationContext Properties

| Property | Type | Description |
|----------|------|-------------|
| `Id` | `string` | Conversation UUID |
| `HistoryLength` | `uint` | Current message count |
| `HasSystem` | `bool` | System prompt set? |

## LLM Streaming

Unity supports token-by-token streaming for LLM models via callbacks:

```csharp
// Check if the model supports streaming
if (model.SupportsTokenStreaming)
{
    using (var envelope = Envelope.Text("Tell me a story about a brave knight."))
    using (var result = model.RunStreaming(envelope, token =>
    {
        // Called for each token as it's generated
        Debug.Log(token.Token);
    }))
    {
        result.ThrowIfFailed();
        Debug.Log($"Full response: {result.Text}");
    }
}
```

### Streaming with Conversation Context

```csharp
using (var context = new ConversationContext())
{
    context.SetSystem("You are a tavern keeper in a fantasy RPG.");

    context.Push("What's on the menu today?", MessageRole.User);
    using (var envelope = Envelope.Text("What's on the menu today?"))
    using (var result = model.RunStreaming(envelope, context, token =>
    {
        Debug.Log(token.Token);  // Each token as it arrives
    }))
    {
        result.ThrowIfFailed();
        context.Push(result.Text, MessageRole.Assistant);
    }
}
```

### Convenience Streaming

```csharp
// Text-in, streaming text-out
string response = model.RunStreamingText("Describe the dungeon entrance.", token =>
{
    // Update UI with each token
    dialogueText.text += token.Token;
});
```

## IDisposable Pattern

All resource-holding classes implement `IDisposable`. Use `using` blocks to ensure cleanup:

```csharp
using (var loader = ModelLoader.FromRegistry("kokoro-82m"))
using (var model = loader.Load())
using (var envelope = Envelope.Text("Your quest is complete, hero."))
using (var result = model.Run(envelope))
{
    result.ThrowIfFailed();
    Debug.Log(result.Text);
}
```

Classes with `IDisposable`: `Model`, `ModelLoader`, `Envelope`, `InferenceResult`, `ConversationContext`

## Error Handling

```csharp
try
{
    var model = XybridClient.LoadModel("nonexistent-model");
}
catch (ModelNotFoundException e)
{
    Debug.LogError($"Model not found: {e.ModelId}");
}
catch (InferenceException e)
{
    Debug.LogError($"Inference failed: {e.Message}");
}
catch (XybridException e)
{
    Debug.LogError($"SDK error: {e.Message}");
}
```

### Exception Hierarchy

| Exception | Description |
|-----------|-------------|
| `XybridException` | Base exception for all SDK errors |
| `ModelNotFoundException` | Model ID not found in registry (has `ModelId` property) |
| `InferenceException` | Inference execution failed |

## Platform Support

| Platform | Architecture | Status |
|----------|--------------|--------|
| macOS | Apple Silicon (arm64) | Supported |
| macOS | Intel (x86_64) | Not supported |
| Windows | x64 | Supported |
| Linux | x64 | Supported |
| iOS | arm64 (devices, iOS 16+) | Supported |
| Android | arm64-v8a, armeabi-v7a | Supported |
| Android | x86_64 | Supported up to Unity 6.4 |

**macOS:** the native library is Apple Silicon (arm64) only. Use the Apple silicon Unity Editor: the Intel editor can't load the library, on an Intel Mac or under Rosetta 2, which runs x86_64 code on Apple Silicon and not the reverse. Build macOS players for **Apple Silicon**. An **Intel 64-bit + Apple Silicon** player can load Xybrid only when it runs natively on an Apple Silicon Mac, not on an Intel Mac or when opened using Rosetta.

**iOS:** the library is built for devices running iOS 16 or later, with no Simulator build. Set **Target minimum iOS Version** to 16.0 or later.

**Android:** Unity 6.5 removed the x86_64 architecture ([announcement](https://discussions.unity.com/t/planned-breaking-changes-in-unity-6-5-updated-2026-03-27/1694205)), and Unity 6.3 and 6.4 offer it only in projects that already target it ([Android Player settings](https://docs.unity3d.com/6000.4/Documentation/Manual/class-PlayerSettingsAndroid.html)). armeabi-v7a ships without ONNX Runtime, so ONNX models such as `kokoro-82m` don't run on it, and its library hasn't been loaded on a device yet ([#680](https://github.com/xybrid-ai/xybrid/issues/680)).
