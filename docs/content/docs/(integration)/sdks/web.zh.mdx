Web SDK（`@xybrid/web`）使用 Xybrid 现有的 Rust llama 封装和 llama.cpp，
将 GGUF 语言模型直接运行在浏览器中。运行时编译为 WebAssembly，在 Worker 内
执行推理，支持逐 token 流式输出、取消生成以及内存与速度测量。
CPU 使用 WASM SIMD；WebGPU 需要支持 `shader-f16` 的适配器。

该包是位于
[`bindings/web`](https://github.com/xybrid-ai/xybrid/tree/master/bindings/web)
的私有 ESM 预览版，尚未发布到 npm。它替换了原有的 LiteRT 张量与文本推理包。
完整的原生 SDK API 和平台服务仍需接入浏览器平台层。

## 构建与运行

安装 Bun、pnpm 和 Bazelisk 后：

```bash
git submodule update --init vendor/llama-cpp
cd bindings/web
pnpm install --frozen-lockfile
pnpm build
pnpm dev:example
```

Bazel 下载固定版本的 Rust 和 Emscripten 工具链，同时构建 CPU 与 WebGPU 运行时。
示例下载并校验 91.7 MB 的 SmolLM2-135M-Instruct Q4_0 GGUF。
运行 `pnpm build:example` 可生成静态网站 `example/dist`，通过 HTTPS 或 localhost 提供服务。

## 加载与流式生成

将 `dist/runtime/` 复制到应用公开的 `/xybrid/runtime/` 目录，并保留包内生成的 Worker。
使用打包工具时导入 `@xybrid/web`；也可以将整个 `dist/` 目录部署到 `/sdk/`，
直接导入 `/sdk/index.js`，并设置 `wasmPath: "/sdk/runtime"`。

```ts
import { XybridLlm } from "@xybrid/web";

const model = await XybridLlm.fromUrl("/models/model.gguf", {
  wasmPath: "/xybrid/runtime",
  accelerator: "auto",
  contextLength: 512,
});
try {
  for await (const delta of model.generateStream("Tell me a short story.", {
    maxOutputTokens: 64,
  })) {
    output.append(delta);
  }
  console.log(model.loaded, model.lastRun);
} finally {
  await model.dispose();
  console.log(model.releasedMemory);
}
```

`generate()` 返回完整字符串。提前退出迭代器会取消解码，并等待原生调用结束。
`cancel()` 显式停止生成；`dispose()` 取消活动任务、释放 Rust 分配并终止 Worker。
同一个模型不允许同时进行多次生成。

## 模型来源

| 方法 | 输入 |
| --- | --- |
| `fromUrl(url, options?)` | GGUF URL，可通过 `sizeBytes` 和 `sha256` 固定并校验文件 |
| `load(url, options?)` | 使用 `Gguf` 执行模板的 Xybrid 元数据 |
| `fromRegistry(id, options?)` | 注册表中的 `gguf` 格式模型 |
| `fromHuggingFace(repo, options?)` | 通过 `file` 和可选的 `revision` 选择顶层 GGUF |

```ts
const model = await XybridLlm.fromHuggingFace(
  "QuantFactory/SmolLM2-135M-Instruct-GGUF",
  { file: "SmolLM2-135M-Instruct.Q4_0.gguf", accelerator: "wasm" },
);
```

注册表响应必须包含 HTTPS 下载 URL、声明大小、SHA-256 和兼容元数据。
Hugging Face 下载会校验声明大小，并在存在有效 Git-LFS OID 时校验 SHA-256。
直接加载也可以提供相同的完整性信息。加载选项支持 `signal` 和 `onDownloadProgress`。

元数据使用 `execution_template.type: "Gguf"`、列于 `files` 中的同目录 `.gguf` 文件名，
以及可选的 `context_length`。模型限制为 512 MiB，元数据限制为 1 MiB，上下文最多
32,768 tokens。运行时资产必须与页面同源；跨域模型服务器需要 CORS。
浏览器只下载选中的 CPU 或 GPU 运行时。

## 测量与当前限制

`loaded` 记录 Rust 版本、后端、模型字节数、下载/初始化/加载耗时和 WASM 内存。
`lastRun` 记录 token 数、首 token 延迟、解码速度、取消状态和采样内存峰值。
`releasedMemory` 记录 Rust 析构后的分配。这些数字不包含 JavaScript 缓冲区、
浏览器进程内存、GPU 分配，以及加载模型或预填充阶段的瞬时峰值。

生成使用 GGUF 内嵌聊天模板、贪心解码、单轮用户输入，并清空 KV 缓存。
直接加载默认使用 512-token 上下文。取消发生在 token 边界；预填充在 Worker 内同步执行。
当前预览不支持外部聊天模板、元数据采样/处理、张量推理、视觉、语音和流水线。

CI 构建两个后端，并在 Chromium 中测试打包后的生产 SDK，上传构建大小与测量结果。
真实 GPU 推理需在兼容硬件上显式启用，或手动触发 `WebGPU browser inference`
工作流，使用标记为 `webgpu` 的自托管 runner。

资产布局、迁移说明与验证命令请参阅
[包 README](https://github.com/xybrid-ai/xybrid/blob/master/bindings/web/README.md)。
