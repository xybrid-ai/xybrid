# @xybrid/react-native example

An Expo app that smoke-tests `@xybrid/react-native` from this repo's source.
On launch it runs through the SDK surface an app touches — version, load,
model info, warmup, run, streaming with a stop button, a two-turn
conversation, structured output, cache status — and, optionally, a speech
round trip (TTS → batch ASR → live ASR session). Every step is timed, shown on
screen, and logged with a `[xybrid-smoke]` prefix, so a device run can be
checked from the logs without tapping anything.

It needs an Expo **development build** (`expo run:ios` / `expo run:android`),
not Expo Go: the package ships native code. The `ios/` and `android/` folders
are generated by `expo prebuild` and are not committed.

## Run it

Build the native core first — the example links your working tree, not a
release.

**iOS** (Apple Silicon Mac, Xcode):

```sh
bazel build --config=ios //bindings/apple:XybridFFI   # from the repo root
cd bindings/react-native/example
npm install
npx expo run:ios
```

`pod install` finds `bazel-bin/bindings/apple/XybridFFI.xcframework.zip` on its
own and syncs the Swift SDK sources from `bindings/apple`.

**Android**:

```sh
# from the repo root: build the AAR and publish the Kotlin SDK to mavenLocal
bazel build -c opt --config=remote //bindings/kotlin:xybrid_kotlin_aar
unzip -o bazel-bin/bindings/kotlin/xybrid-kotlin.aar 'jni/*' -d /tmp/aar
cp -r /tmp/aar/jni/* bindings/kotlin/libs/
(cd bindings/kotlin && ./gradlew publishToMavenLocal)

cd bindings/react-native/example
npm install
npx expo run:android
```

The config plugin in `plugins/withXybridDevAndroid.js` puts `mavenLocal()`
first, so the app links the Kotlin SDK you just published.

## Choosing models

Defaults to `lfm2.5-230m` from the registry. Override when starting Metro:

```sh
# A registry id, or a local model directory / .gguf file on the device
EXPO_PUBLIC_XYBRID_SMOKE_MODEL=qwen3.5-0.8b npx expo start

# Add the speech round trip: "<tts>,<asr>"
EXPO_PUBLIC_XYBRID_SMOKE_SPEECH=kitten-tts-nano-0.8,whisper-tiny-ggml npx expo start
```

On a device without network access, push a cached model into the app's
sandbox and pass its path:

```sh
adb push ~/.xybrid/cache/extracted/lfm2.5-230m /data/local/tmp/
adb shell "run-as com.anonymous.example mkdir -p files/smoke/lfm2.5-230m && \
  cd /data/local/tmp/lfm2.5-230m && for f in *; do \
  cat \$f | run-as com.anonymous.example sh -c \"cat > files/smoke/lfm2.5-230m/\$f\"; done"
EXPO_PUBLIC_XYBRID_SMOKE_MODEL=/data/user/0/com.anonymous.example/files/smoke/lfm2.5-230m npx expo start
```

## Notes

- Watch the logs with `adb logcat -s ReactNativeJS` (Android) or the Metro
  terminal.
- LLM output on the **iOS Simulator** is garbage today: llama.cpp offloads to
  Metal, which the simulator does not support. Use a device, or Android.
- `metro.config.js` pins `react` and `react-native` to this app's copies, so a
  `node_modules` in `bindings/react-native` can never put a second React
  Native in the bundle.
